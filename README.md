# Voltdrop — 충전 계측 앱

배터리를 거의 쓰지 않으면서 충전을 실시간으로 들여다보는 안드로이드 앱.

---

## 1. 배터리를 안 먹는 이유

이런 앱이 배터리를 잡아먹는 원인은 딱 세 가지다. 셋 다 피했다.

**① 잘못된 브로드캐스트 등록**

대부분의 배터리 앱은 `ACTION_BATTERY_CHANGED` 를 리시버로 등록한다. 이건 초당 수십 번 날아오고, 그때마다 앱 프로세스가 깨어난다. 이게 진짜 범인이다.

Voltdrop은 이걸 **등록하지 않는다.** 대신 `registerReceiver(null, filter)` 로 sticky broadcast를 그냥 읽는다. 시스템이 이미 메모리에 들고 있는 마지막 값을 꺼내오는 것이라, 프로세스를 깨우지도 센서를 돌리지도 않는다.

매니페스트에는 꽂힘/뽑힘 두 이벤트만 등록한다. 하루에 서너 번뿐이다.

**② 상시 폴링**

주기를 상황에 맞춰 바꾼다.

| 상황 | 주기 | 이유 |
|---|---|---|
| 앱 화면 보는 중 | 1초 | 게이지가 살아 움직여야 하니까 |
| 화면 꺼짐 + 충전 중 | 30초 | 기록만 남기면 되니까 |
| 충전기 뽑힘 | **0회** | 루프를 아예 없앤다 |

`ChargingRepository.startForeground()` / `startBackground()` / `stop()` 이 이 전환을 담당한다. `MainActivity.onPause()` 에서 앱 루프는 완전히 정지하고, 서비스가 30초 간격으로 이어받는다.

**③ wakelock**

안 잡는다. Doze 모드에 들어가면 같이 잠들고, 시스템이 깨울 때만 기록한다. 충전 중엔 어차피 Doze가 잘 안 걸리고, 걸리더라도 그래프에 30초 구멍이 나는 정도다.

**그리고 결정적으로**, 이 서비스는 충전기가 꽂혀 있을 때만 산다. 전기가 들어오는 동안에만 쓰는 전기라 실사용 배터리에는 영향이 없다. 뽑는 순간 `stopSelf()` 로 죽는다.

권한도 네트워크·위치·저장소 전부 없다. 알림과 포그라운드 서비스 두 개가 전부다.

## 2. 요청한 기능

- **실시간 W** — 배터리 전압 × 보정된 전류. 최근 5개 중앙값으로 스파이크 제거
- **물방울 게이지** — 물 높이 = 잔량, 물결 속도·진폭 = 전력. 두 겹 사인파가 다른 속도로 흘러 겹칠 때 밀도가 생긴다
- **계기판 게이지** — 바늘 + 눈금. 같은 데이터, 다른 표현
- **완충 예상 시간** — 80% 전후를 나눠서 계산한다. 그냥 나누면 뒷구간이 항상 틀린다 (CV 구간에서 전류가 절반 이하로 떨어지니까)
- **온도** — 40°C 넘으면 색이 바뀐다
- **유선/무선 구분** — `EXTRA_PLUGGED` 로 AC / USB / 무선 / 독 판별
- **스로틀링 시점** — 아래 참조
- **충전 습관** — 완충 방치 시간, 40°C 초과 노출, 밤샘 충전 비율, 실제 유입 효율

## 3. 다른 앱에 없는 것

**스로틀링의 원인을 나눈다.**
대부분의 앱은 "느려짐" 하나로 뭉뚱그린다. Voltdrop은 셋으로 나눈다.

- `SOC_TAPER` — 80% 이상에서 감속. **정상이다.** 리튬 배터리는 원래 이렇게 동작한다
- `HEAT` — 온도가 오르며 감속. 케이스를 벗기면 회복된다
- `SOURCE_LIMIT` — 온도도 잔량도 그대로인데 감속. 충전기나 케이블 쪽 문제다

같은 20W → 9W라도 원인이 다르면 대응이 완전히 다르다. 이 구분이 이 앱의 핵심이다.

**계기판에 각인이 남는다.**
스로틀이 걸린 지점마다 눈금 위에 색 표시가 박히고, 세션 최고 기록 자리엔 흰 점이 박힌다. 바늘이 지금 어디 있는지뿐 아니라 **왜 거기까지밖에 못 갔는지**가 한 화면에 보인다.

**충전기 지문.**
전압 + 피크 전력 + 상승 시간 조합이 충전기·케이블마다 꽤 뚜렷하게 다르다. 이걸로 같은 충전기를 알아보고 이름을 붙여둔다. 그리고 **같은 충전기인데 평소보다 15% 넘게 못 나오면 케이블 열화를 의심하라고 알려준다.** 이건 기기 하나에 대한 장기 기록이 있어야만 가능한 기능이다.

**전류 센서 자동 보정.**
제조사마다 `CURRENT_NOW` 를 µA로도 주고 mA로도 주고, 충전 중에 음수로 주는 기기도 있다. 그대로 믿으면 어떤 폰에선 27W가, 다른 폰에선 0.027W가 뜬다. 대부분의 앱이 여기서 틀린다.

Voltdrop은 단위가 표준인 `CHARGE_COUNTER`(µAh) 변화량으로 실제 평균 전류를 역산해서 배율과 부호를 스스로 찾는다. 꽂아두고 1분이면 끝나고, 결과는 저장된다. → `BatterySampler.feedCalibration()`

## 5. 알아둘 것

측정되는 W는 **배터리 셀에 실제로 들어가는 전력**이지 어댑터 출력이 아니다. 65W 어댑터를 꽂아도 화면엔 30W대가 뜨는 게 정상이다. 나머지는 전압 변환 손실과 발열로 나간다. `실제 유입 효율` 항목이 그 차이를 보여준다.

`ChargerRegistry` 와 `SessionStore` 는 지금 메모리 저장이다. 실제 배포 전엔 Room으로 교체해야 한다. 세션이 끝날 때만 쓰기 때문에 DB 쓰기 비용은 하루 몇 번 수준이다.
